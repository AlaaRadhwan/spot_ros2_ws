# Spot ROS 2 / Gazebo Workspace

ROS 2 and Gazebo simulation workspace for deploying and validating the Spot V3 locomotion system developed in [`spot_locomotion_v2`](https://github.com/AlaaRadhwan/spot_locomotion_v2).

The goal of this workspace is sim-to-sim deployment of a reinforcement-learning locomotion policy trained in MuJoCo/MjLab into ROS 2 + Gazebo while keeping the robot dynamics, joint controller behavior, observation pipeline, and action semantics as consistent as practical.

## Current Platform

- Ubuntu 24.04
- ROS 2 Jazzy
- Gazebo Harmonic
- `gz_ros2_control`
- Effort-controlled joints

## Spot V3 Model

The Gazebo model is based on the V3 rigid-body model used for MuJoCo training.

### Mass

Total rigid-body mass:

```text
31.5999994 kg
```

Main link masses:

```text
Body:       16.707651 kg
Hip:         1.1368834 kg each
Upper leg:   2.2562037 kg each
Lower leg:   0.3300000 kg each
```

The Gazebo model uses the same V3 link masses, COM locations, inertias, joint layout, joint limits, and nominal pose used in the MuJoCo model.


## Nominal Pose

```text
HX =  0.00 rad
HY =  1.04 rad

```

for all four legs.

## Low-Level Controller

Gazebo uses an effort-interface PID controller through `ros2_control`.

The target control law is:

```text
tau = Kp * (q_ref - q) - Kd * qdot
```

with:

```text
Kp = 300
Kd = 40
Ki = 0
```

Torque limits:

```text
HX / HY: ±45 Nm
Knee:    ±115 Nm
```

The ROS controller receives joint position references and zero desired joint velocity.

## Timing

Current validated Gazebo configuration:

```text
Gazebo physics:        2000 Hz
ros2_control PID:      2000 Hz
RL policy target rate:   50 Hz
```

The RL policy will generate a new joint-position reference every 20 ms. The low-level controller holds that reference and updates joint effort at 2000 Hz.

### Why 2000 Hz?

The same `Kp=300`, `Kd=40` controller was initially tested with Gazebo physics and `ros2_control` both running at 500 Hz.

At 500 Hz, the robot developed severe joint oscillations and repeatedly saturated the actuator effort limits.

Without changing the gains or effort limits, increasing both Gazebo physics and the low-level controller to 2000 Hz produced stable standing.

Current baseline:

```text
500 Hz:
300 / 40
±45 / ±115 Nm
→ unstable oscillation

2000 Hz:
300 / 40
±45 / ±115 Nm
→ stable
```

The MuJoCo training environment remains at 500 Hz physics. The difference is important because MuJoCo uses a native actuator with an implicit dynamics integration scheme, while the Gazebo implementation applies the PD controller through an external effort interface.

`build/`, `install/`, and `log/` are generated by `colcon` and are not tracked by Git.

## Build

```bash
cd ~/Projects/spot_ros2_ws

source /opt/ros/jazzy/setup.bash

colcon build --symlink-install

source install/setup.bash
```

## Launch Gazebo

```bash
ros2 launch spot_gazebo spawn_spot.launch.py
```

Check controllers:

```bash
ros2 control list_controllers
```

Expected:

```text
spot_joint_controller    active
joint_state_broadcaster  active
```

Check hardware interfaces:

```bash
ros2 control list_hardware_interfaces
```
